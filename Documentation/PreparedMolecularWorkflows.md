# Prepared molecular systems, sampling and chemistry-to-rate integration

This increment extends the existing molecular structures, native force-field compiler, Metal MD runtime, density fitting, correlated solvers, artifact DAG, nuclear qualification and kinetic derivation. It does not introduce a second solver, MD engine, thermochemistry implementation or artifact store.

**Validation is revision-specific.** The [prepared-reaction audit](Audit/2026-09-08_PREPARED_REACTION_CAMPAIGN.md) records a complete finite preparation-through-observable campaign through both the SDK and public CLI. The earlier [sampling/export audit](Audit/2026-09-08_SAMPLING_EXPORT.md) records accepted-prefix continuation and electronic handoff; the [MD numerical audit](Audit/2026-09-08_MD_NUMERICAL_QUALIFICATION.md) records separate scientific fixtures. These results do not establish realistic protein rates or general chemical accuracy.

## 1. Explicit molecular preparation

`VivoMolecularPreparation.prepare` is a transaction over the existing canonical structure. A request retains the source structure, chosen protonation microstate, source identifier, pH, formal charge, ordered stereochemical constraints and optionally the native parameter library.

The implementation removes only singly attached physical hydrogens; adds explicitly identified hydrogens using internal coordinates; edits formal charges and residue-state names; updates every conformer; and retains source-to-prepared and prepared-to-source atom maps. Generated hydrogens have no fabricated source atom index. Source potential energies are cleared after topology, charge or residue-state edits. Such edits require coordinate relaxation before physical use. The existing alternate-location resolver may retain the selected A/B label; duplicate atom sites, not the mere presence of that label, are rejected.

Tetrahedral constraints use the sign of a volume defined by **four explicitly ordered bonded neighbors**. Double-bond constraints use explicitly chosen substituents and their projected orientation. Every conformer must satisfy the supplied constraints. These are not an incomplete CIP implementation disguised as R/S or E/Z assignments. Unspecified stereocenters are not inferred, and the existing SMILES/SDF stereo import restrictions are unchanged.

pH is recorded context. The preparation request does **not** calculate pKa values, infer equilibrium microstate populations, enumerate tautomers, or provide constant-pH dynamics. The caller must select and identify the microstate. Hydrogen coordinates are initial guesses, not optimized conformers.

### Commands

Start from a canonical `VivoMolecularStructure` JSON generated by the existing structure import/preparation commands and a validated native parameter library:

```sh
numivivo molecule-prepare-template structure.json \
  --microstate selected-state --pH 7.4 \
  --protonation-source curated-state-record \
  --forcefield native-library.json --output preparation.json

# Edit the explicit hydrogen, charge, residue and stereo records as needed.
numivivo molecule-prepare preparation.json --output prepared.json
```

The output is a `VivoMolecularPreparationResult`. Its optional `compiledForceField` contains the existing `VivoClassicalSystem`. Without a library, preparation can return geometry/topology but cannot supply a parameterized MD system. A sibling `.receipt.json` records the artifact task identity for pure workflow commands.

### Native parameter completeness and improper torsions

Strict preparation assignment checks complete residue atom names, intrarezidue connectivity and bond order against the selected template; all atoms must be resolved and the total partial charge must agree with the explicit formal charge. Missing parameters are errors, not zero-energy terms.

Native residue templates now optionally contain `impropers`. Each record has `orderedAtoms` (four atom names in the force field's intended dihedral order) and a separately declared `center`. The center must be bonded to the other three atoms. The compiler passes these terms into the existing `VivoPeriodicTorsion`/classical force kernels.

**Migration rule:** when an improper-parameter library is used, a legacy template with `impropers: null` or no field is unspecified and fails compilation. An explicit empty array means no local impropers. Supply ordered recipes where they are required; do not replace missing recipes with empty arrays just to pass validation. Cross-residue additions use `VivoForceFieldCompilationOptions.additionalImproperTorsions`. Their indices address the **prepared** canonical structure supplied to the compiler, not the pre-edit source structure.

Proper and improper torsions use the same parameter matcher: the most specific matching family wins, all Fourier terms in that family are retained, and competing equally specific families are rejected. Only full dihedral reversal is considered equivalent; peripheral atoms are not sorted or permuted to force a match. Repeated type tuples are cached during compilation.

The compiler does not synthesize a transferable organic/protein force field, perform universal atom typing, or independently validate the physical accuracy of a supplied library. Existing imported AMBER canonical systems remain usable through their existing path.

## 2. Periodic geometry

The public `VivoPeriodicCell.minimumImage` now uses the existing bounded exact reciprocal-lattice closest-image search instead of fractional rounding. Structural selection, topology and finite-cluster preparation callers therefore share the same triclinic geometry implementation. Ill-conditioned cells that exceed the bounded search remain explicit errors.

`VivoPeriodicCell.crystallographic(lengthsNM:anglesDegrees:)` constructs a right-handed cell from lengths and alpha/beta/gamma angles. `faceHeightsNM` provides perpendicular face distances, and `validateSingleImageRadius` enforces a conservative half-face-height bound. Include the neighbor skin when checking a pair-list radius.

**This is not arbitrary-triclinic Metal execution.** The production Metal force, constraint, neighbor and PME paths retain their existing orthogonal-cell preflight. The new sampling runner calls that preflight. A geometrically representable triclinic structure is not automatically an executable GPU periodic system.

## 3. Practical density-fitting and correlated-solver integration

The existing RI factors now support a rectangular molecular-orbital pair panel. DF-MP2 transforms only occupied-virtual factors, computes each unordered occupied pair once, contracts its virtual-pair matrix with the existing dense algebra implementation and uses compensated correlation-energy summation. Restricted Hartree–Fock reuses the identical spin J/K contraction. Arithmetic-work budgets are separate from allocation budgets.

RI-HF artifact validation reconstructs the density, overlap metric, canonical Fock representation, physical reference energy and commutator directly. It no longer executes MP2 merely to validate an HF reference or imposes an MP2 gap condition on a correlated-solver preparation request.

`VivoRIActiveSpace` explicitly lists active canonical orbitals and frozen doubly occupied orbitals. Every occupied orbital must be accounted for. Frozen-core J/K and its scalar contribution are computed in the AO basis, and active factors produce the **existing** `VivoEmbeddedHamiltonian`. The parent AO/full-MO four-index ERI tensors are not constructed.

Additive cases in `VivoAdvancedElectronicCalculation` are:

- `densityFittedCorrelated(configuration:space:solver:)`
- `densityFittedEmbedding(configuration:space:embedding:)`
- `densityFittedDMET(configuration:space:embedding:)`

They run through the existing `chemistry-run`/`chemistry-solve`, DAG and downstream many-body/ECC/DMET operations. Auxiliary basis, fitting threshold, selected orbitals, frozen-core partition, physical scalar and method provenance are retained. There is no automatic fallback to another solver or a smaller model.

**Scaling limits remain:** the auxiliary metric is dense; factors are in memory; the current correlated/embedding boundary materializes the selected active `m^4` tensor. Determinant and embedding costs remain those of the selected existing solver. Canonical active orbital indices are not transported reaction-path orbitals. These changes reduce avoidable work; no throughput or larger-system accuracy claim is made without execution data.

## 4. Adaptive molecular sampling with the existing Metal runtime

`VivoMolecularSamplingRunner` executes explicitly seeded replicas under one Langevin NVT/NPT model. It uses one existing Metal MD arena at a time, minimizing/thermalizing only new replicas and restoring the existing exact accepted-state checkpoints for continuation. Coordinates stream through the existing bounded trajectory archive; scalar observable traces retain their archive identities.

A complete cross-replica block is the durable publication boundary. Diagnostics can extend sampling until the required consecutive passes or the declared budget is exhausted. A failed block does not replace the last complete checkpoint. Cancellation, numerical rejection and budget exhaustion are distinct from convergence.

```sh
numivivo molecule-sampling-template prepared.json \
  --context solution-state-A --distance 0,1 \
  --temperature 298.15 --output sampling.json

# Replace the illustrative observables/budgets with those required by the system.
numivivo molecule-sampling-run sampling.json \
  --store .numivivo/chemistry-artifacts --output sampling-result.json

# Resume the same request from a retained molecular-sampling checkpoint digest.
numivivo molecule-sampling-run sampling.json \
  --store .numivivo/chemistry-artifacts --resume LOWERCASE_SHA256 \
  --output continued-sampling-result.json
```

The runner publishes `molecular-sampling-<request-sha256>-checkpoint` in the existing artifact store. The receipt contains that checkpoint, trajectory manifests, status and latest diagnostics. Outputs are no-clobber; use a new output filename when continuing. The generated schedule is only a starting configuration, not a universal equilibration duration. Distinct velocity seeds do not establish diverse initial conformations.

The [accepted sampling export interface](Design/MOLECULAR_SAMPLING_EXPORT.md) validates a selected completed prefix and publishes its exact checkpoint, source model, snapshot and atom mapping as existing typed workflow outputs. The export retains partial termination and declared stopping criteria separately, and its immutable receipt can be freshly verified independently of cache references.

The [geometry-seed and encounter interfaces](Design/PREPARED_REACTION_CAMPAIGN.md) extend that handoff into fresh nuclear/reaction qualification and a conditional observable. `reaction-seed` changes only explicitly mapped initial coordinates; `reaction-seed-verify` rechecks the immutable source chain. `reaction-encounter-request` binds explicit tagged-component, reservoir and time conditions for the `vivo.native.conditional-encounter` workflow operation. The [complete published example](../Examples/prepared-reaction/README.md) uses a partial sampling prefix only as geometry, with fresh chemistry and separately declared bath assumptions.

Geometry observables use explicit **structure-atom to physical-particle** maps, so virtual-site indices are not mistaken for atom indices. Supported observables are distances, distance differences, torsion sine/cosine, potential energy, temperature and periodic volume. Sine/cosine avoids an angular discontinuity at a torsion branch cut.

Diagnostics use rank-normalized and folded split-Rhat, multi-chain initial-positive/initial-monotone effective sample counts, 5%/95% tail indicators and raw-scale uncertainty in each observable mean. Constant traces, unresolved autocorrelation tails, insufficient effective samples and insufficient precision fail. Scalar storage and autocorrelation work have explicit bounds. The standalone `molecule-sampling-analyze` command consumes `VivoMolecularSamplingRequest` and returns the same reconstructible result.

These diagnostics apply to the **declared observables and sampling Hamiltonian**. They do not prove global exploration, reaction-coordinate overlap, QM equilibrium, force-field accuracy, protonation-state populations or a converged activation PMF. A temperature or electrostatic-energy trace alone cannot qualify molecular reaction sampling.

Method reference: Vehtari et al., *Rank-Normalization, Folding, and Localization: An Improved R-hat for Assessing Convergence of MCMC*, Bayesian Analysis 16 (2021), 667–718, doi:10.1214/20-BA1221. Operational definitions are also documented by Stan's posterior package at https://mc-stan.org/posterior/reference/rhat.html and https://mc-stan.org/posterior/reference/ess_bulk.html. No Stan dependency is introduced.

## 5. Connected stationary points and conditional rates

`VivoConnectedReactionRequest` supplies an explicit saddle seed, two explicitly mapped endpoint definitions, their individual qualification requests, path-refinement criteria, reactant identity and transmission declaration. The existing workflow operation runs, in order:

1. Existing nuclear minimization/saddle refinement and derivative/RRHO qualification.
2. Existing mapped bidirectional descent with independent displacement and step refinements.
3. Existing molecular transition-state-theory calculation with declared molecularity and standard-state units.

Identical endpoint requests share one calculation-local result. Atom, isotope, electronic model, temperature, standard-state and budget mismatches are errors. Seeds are not treated as characterized stationary points.

```sh
numivivo reaction-template h3-connected-rate --output connected-reaction.json
numivivo reaction-run connected-reaction.json \
  --store .numivivo/chemistry-artifacts --output connected-result.json
```

This H + H2 identity-exchange case is a **small covalent workflow fixture**, not a validated carbon/sulfur reaction or a protein-barrier demonstration. It reuses the existing H3/H2/H seeds. A realistic covalent reaction requires its own prepared reactants, saddle seed, electronic model, mapped endpoints and convergence study. No new benchmark result is claimed in this increment.

### Prepared rate to the existing kinetic model

`VivoPreparedReactionRateRequest` combines the original preparation request, converged molecular sampling result, existing TST request, exact `VivoKineticContext` and an explicit classical-to-electronic model-transfer description. It reconstructs preparation and diagnostics and requires complete atom mapping, matching microstate/pH/temperature/host context and the same prepared classical system.

For a pre-reactive **unimolecular complex** in an isolated or continuum model, the adapter calls both the existing molecular TST and existing `VivoTransitionStateDerivation`, checks their log-rate agreement, retains their evidence and can apply the resulting inactivation parameter to an exactly context-matched kinetic pack:

```sh
numivivo molecule-rate prepared-rate-request.json --output conditional-rate.json

numivivo molecule-rate prepared-rate-request.json \
  --kinetics matching-kinetic-pack.json --output conditional-rate-with-pack.json
```

The latter writes a separate `.kinetics.json` and retains association, dissociation and turnover. The command does not derive those parameters from a unimolecular barrier. Separated reactants retain the existing molecular TST concentration/pressure rate; they are not silently relabeled as a bound-complex first-order rate.

The prepared-rate request is a domain-specific assembly, not an automatically inferred transformation. In Swift it is constructed with `VivoPreparedReactionRateRequest(context:environment:preparation:sampling:transitionState:modelTransferDescription:)`, using the sampling receipt's converged `sampling` result and the connected reaction result's `request`. The context and endpoint identities must describe the same actual complex. A multicomponent H3 fixture cannot be inserted into this unimolecular bridge.

**The generated kinetic parameter remains `assumed`, with unknown total uncertainty.** The adapter explicitly retains unresolved conformer/protonation populations, classical-to-QM reweighting, configurational/anharmonic terms and any missing solvent contributions. Computed or experimental transmission requires a source locator, retained evidence bytes and a matching content digest; merely hashing a coefficient declaration is not independent evidence. Evidence integrity does not independently establish the physical accuracy of the supplied dynamics or measurement.

## 6. Protein progression and remaining completion work

Prepared protein systems can use the existing MD and exact checkpoint path into `VivoQMMMCompiler.prepareMD`, documented in the [MD to QM/MM interface](Design/MD_QMMM_INTERFACE.md). That interface retains periodic unwrapping, whole molecules, virtual sites and the finite-cluster atom map. The adaptive sampler's exact MD checkpoints can feed that existing interface; a coordinate-only trajectory frame must not acquire fabricated velocities and be presented as a genuine restart snapshot.

The prepared-rate adapter **rejects `proteinEnvironment`**. Free-molecule RRHO removes rigid modes that are not free in a frozen external environment; electrostatic C-PCM convergence does not supply solvent entropy, nonpolar terms or protein reorganization. The current work does not implement a complete protein activation free-energy estimator, constrained/environment thermochemistry, enhanced reaction sampling/PMF, microstate population integration or dynamical transmission calculation.

The next physical completion is a single consistent sampled QM/MM free-energy model, including environment relaxation, restraint/standard-state accounting and uncertainty, followed by a small chemically realistic covalent benchmark and transfer into its protein environment. Reusing the existing stationary-point and solvent components is necessary but is not sufficient evidence that this completion has occurred.
